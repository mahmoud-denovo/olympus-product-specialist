# Mock Data & Component Registry

## 1. Overview
In compliance with the **Mandatory Mock Data Transparency Directive**, this document registers all mock data structures, fallback catalogs, simulated hardware models, and stubbed API responses utilized across the `olympus-product-specialist` system.

All simulated outputs generated by fallback mechanisms or static catalogs are tagged with `[MOCK_DATA]`.

## 3. Fallback and Simulation Behaviors

1. **Database Fallback**: `SequentialThinkingEngine._merge_catalog_from_db()` falls back to `_load_default_catalog()` if the SQLite file cannot be read or is corrupted. Output is tagged with `[MOCK_DATA]`.
2. **HitL Non-Interactive Automation**: In non-interactive mode (`--non-interactive`), `HITLHandler` automatically selects `choices[0]` without interactive prompts.
3. **CLI Presentation Banner**: `RichFormatter.render_header()` explicitly identifies the system operating in simulated/mock mode.
